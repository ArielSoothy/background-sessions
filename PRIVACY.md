# Privacy

session-board does not open conversation transcripts or capture turn replies, and never edits Claude Code’s own session files directly.

The Python helper opens and parses each job’s `state.json` in memory. It uses exactly `sessionId`, `cwd`, `originCwd`, `state`, `name`, `color`, `createdAt`, `updatedAt`, `lastTerminalAt`, and `inFlight.tasks`. Every other field (which can include the job’s prompt/intent and status detail) is discarded immediately after parsing, never stored or sent. Project grouping uses the working folder, configured roots and an optional explicitly configured JSON catalog. It compares realpaths and walks upward for a `.git` entry without reading its contents or running Git, stopping at the user’s home directory and never above it.

It queries its own session's usage and model APIs. It stores numeric tokens, context window size, percentage, timestamp, session id and model identifier under `<Claude root>/session-board/usage/<session-id>.json`. Other sessions' usage and model appear only when those sessions also report through this plugin. It writes close markers with a timestamp and reason under `done/<session-id>.json` in the same plugin folder. Close markers may also store `suffixName`, the exact title with the suffix added by the plugin.

The Claude root is CLAUDE_CONFIG_DIR, or HOME/.claude when that variable is unset. An absolute CLAUDE_CONFIG_DIR works without HOME. HOME is needed only for the default root or `~` expansion. The configured root must already exist; only the plugin’s own data subfolder can be created. Trusted roots are resolved once per operation, allowing symlinked config roots and ancestors; symlinks below those resolved roots are refused. Settings and empty opt-out files in the plugin folder are user-managed. Automatic renaming is on by default: it puts the project short name or folder name into the session title through `/rename`. Set `SESSION_BOARD_NO_RENAME=1` or create `<Claude root>/session-board/no-rename` to turn it off, including done suffix changes. A manual `/rename` disables all further automatic renaming for that session, including adding and removing the done suffix. Name and colour changes use only the running session's built-in `/rename` and `/color` commands. There are no direct writes to the host's jobs folder.

Persistent Claude plugin storage contains per-session prefix/colour ownership records, including the last managed host name (`lastSet`). Session names stored as `lastSet` or `suffixName` may come from Claude Code’s own auto-generated name, which can be derived from the conversation. Transient plugin state holds the board snapshot and startup flag. A fresh process startup clears its own close marker; a hook reload preserves it. Startup removes a done suffix only if the marker records the exact current title as one the plugin added and automatic renaming is still enabled. Collection prunes usage/done files and persistent per-session records when their jobs no longer exist, while retaining usage/done records and store records for the running foreground session. Cleanup also prunes stray `*.tmp` files in the plugin’s own data folders. Unreadable job inventories do not drive pruning. Read-only mode disables file writes, pruning, persistent store changes and automatic name/colour commands.

The plugin itself sends nothing off the machine, makes no network requests and makes no model calls. It injects nothing into messages or session context. Its only child process is the local Python metadata helper, which runs only for interactive sessions and is skipped for print/headless sessions. Helper failures cause a ten-minute backoff for collection and record writes.

To clear local plugin files, remove the `session-board` folder under the active Claude root using your file manager while the plugin is disabled. Clear the plugin's persistent storage using Claude Code's plugin management controls. Uninstall or disable the plugin to prevent future reports. Names or colours already set through built-in commands remain until you change them. No remote copy is created by this plugin.

Report privacy issues through [GitHub issues](https://github.com/ArielSoothy/session-board/issues); do not include private metadata in public reports.
